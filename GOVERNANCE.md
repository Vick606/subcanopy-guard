# Governance

## Model

Subcanopy Guard uses a **benevolent dictator** model. The maintainer
listed in [MAINTAINERS.md](MAINTAINERS.md) has final say on all decisions.

## How decisions are made

| Decision type | Process |
|---|---|
| Bug fixes, docs, tests | Merged by maintainer after review |
| New detection signals | Discussed in a GitHub Discussion first |
| Breaking API changes | Requires a new major version and a deprecation notice |
| Licensing changes | Requires a new major version and a CLA re-sign |
| Adding a maintainer | By invitation from the current maintainer |

## Why this model

The project is small and opinionated. Consensus-based governance adds
overhead without improving outcomes at this scale. If the project grows
to the point where a single maintainer is a bottleneck, this document
will be revised.

## Amendments

Changes to this document require a pull request and the maintainer's
approval.
